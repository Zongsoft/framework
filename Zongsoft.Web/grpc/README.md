## Overview

[**Z**ongsoft.**W**eb.**G**rpc](https://github.com/Zongsoft/framework/tree/main/Zongsoft.Web/grpc) is the [_**g**RPC_](https://grpc.io) plugin library in the [_**Z**ongsoft_](https://github.com/Zongsoft/framework) open-source framework. It initializes the [_**g**RPC_](https://grpc.io) runtime environment for host programs.

It adds server registration and endpoint discovery to a Zongsoft web host. It hosts generated gRPC service bases; it does not define application contracts or generate `.proto` files.

## Installation and Deployment

```shell
dotnet add package Zongsoft.Web.Grpc
```

Deploy `Zongsoft.Web.Grpc.plugin` with the assembly. The package registers `Grpc.AspNetCore.Server` and server reflection.

## Service Discovery

Implement a service base generated by `Grpc.Tools`, register the concrete type through the framework service system, and assign it the `gRPC` tag. At startup `GrpcInitializer.Registration` calls `AddGrpc` and `AddGrpcReflection`; `GrpcInitializer` reads tagged types, invokes `MapGrpcService<T>`, and maps reflection.

> 💡 The `gRPC` tag is the discovery contract. A DI registration without that tag is not mapped by this initializer.

## Hosting Notes

gRPC normally uses HTTP/2 and Protocol Buffers. Configure Kestrel, TLS, proxies, message limits, deadlines, and compression according to the [ASP.NET Core gRPC guidance](https://learn.microsoft.com/aspnet/core/grpc/). Propagate `ServerCallContext.CancellationToken` through downstream work.

🚨 Server reflection reveals service metadata and is mapped by this package. Restrict access at the network and authorization layers when the deployment must not publish its contract surface.

## Plugin-Based Integration

Compose this feature through the host; a package reference supplies compile-time APIs, while plugin loading also requires deployed manifests and runtime assets. See [the complete plugin workflow](../../Zongsoft.Plugins/README.md).

Use a Plugins.Web host. The initializer registers gRPC and maps service types tagged `gRPC`; deploy the actual protocol/service plugin as well. HTTP/2 endpoint and reflection exposure remain explicit host decisions.

| Runtime artifact | Source of truth |
| --- | --- |
| `Zongsoft.Web.Grpc` | [Zongsoft.Web.Grpc.plugin](Zongsoft.Web.Grpc.plugin) |
| File copying and dependencies | [Zongsoft.Web.Grpc.deploy](Zongsoft.Web.Grpc.deploy) |

Add this fragment to an existing host `.deploy` (retain Main and the host’s other base manifests; do not replace the whole file):

```ini
[plugins zongsoft web grpc]
nuget:Zongsoft.Web.Grpc
```

Run `dotnet deploy` against a test deployment as explained in the workflow, with the host's `framework`, `platform`, `architecture` and, where needed, `site`. Pin compatible versions in real deployments; application dependencies such as databases, caches or commercial runtimes are still separate prerequisites.

Additional artifacts listed by the deployment manifest include `Zongsoft.Web.Grpc.plugin`. Retain assemblies, dependencies and satellite resource directories as well. Restart the host after deployment, check plugin loading and service/driver registration, then verify the workflow above; copied files alone do not prove that the feature is active.
