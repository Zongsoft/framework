## Overview

[**Z**ongsoft.**W**eb.**G**rpc](https://github.com/Zongsoft/framework/tree/main/Zongsoft.Web/grpc) is the [_**g**RPC_](https://grpc.io) plugin library in the [_**Z**ongsoft_](https://github.com/Zongsoft/framework) open-source framework. It initializes the [_**g**RPC_](https://grpc.io) runtime environment for host programs.

It adds server registration and endpoint discovery to a Zongsoft web host. It hosts generated gRPC service bases; it does not define application contracts or generate `.proto` files.

## Installation and Deployment

```shell
dotnet add package Zongsoft.Web.Grpc
```

Deploy `Zongsoft.Web.Grpc.plugin` with the assembly. The package registers `Grpc.AspNetCore.Server` and server reflection.

## Service Discovery

Implement a service base generated by `Grpc.Tools`, register the concrete type through the framework service system, and assign it the `gRPC` tag. The private `GrpcInitializer.Registration` registers the protocol policy, gRPC server and regional reflection wrapper. `GrpcInitializer` reads each tagged type's `Handler` attributes and mounts the service in the corresponding Web endpoint regions.

> 💡 The `gRPC` tag is the discovery contract. A DI registration without that tag is not mapped by this initializer.

### Base paths and regions

Declare a literal base path on each concrete business service; the generated protocol service and method names stay unchanged:

```csharp
[Zongsoft.Services.Service(Tags = "gRPC")]
[Zongsoft.Components.Handler("/orders")]
public class OrderService : Orders.OrdersBase
{
	// Implement the methods generated from the application's proto file.
}
```

The plugin's option file declares the same path in its listening URL:

```xml
<?zongsoft.tools.binding path="Kestrel/Endpoints/*" template="${this.Url}" protocols="${this.Protocols}"?>
<options>
	<option path="Kestrel">
		<endpoints>
			<orders url="http://*:4317/orders" protocols="grpc+http2" />
		</endpoints>
	</option>
</options>
```

A generated `/demo.Orders/Get` RPC is then mounted at `/orders/demo.Orders/Get`. Clients must send that full path; supplying a base path to an unadapted `GrpcChannel.ForAddress` is insufficient. No `/grpc` prefix is inserted automatically.

`Handler.Template` associates with a declared gRPC base path ignoring case and an optional trailing slash; /orders and /Orders/ are equivalent. Templates match only the base path. Callers supply native service and method names with the exact protocol casing, which the gRPC adapter validates without rewriting the request. Root services explicitly use `[Handler("/")]`; `Order` must be zero. Inherited and repeated attributes are read, duplicate paths are removed, and a type may be mounted at several paths without changing its DI lifetime. Several types can share a region, and the same region on several listeners exposes the same services. Missing attributes, unmatched paths, empty business regions, conflicting protocol services/methods, and invalid paths fail initialization.

Each region has a lowest-priority unknown-RPC endpoint that returns `UNIMPLEMENTED`; it cannot fall back to a shorter region or another listener. The global and service-specific `IgnoreUnknownServices` options must not disable this arrangement: the registration sets the global value to true, and inconsistent options fail initialization. The fallback remains in the normal authorization pipeline; per-service authorization attributes are not copied to a region containing several services.

Reflection is mounted in each region using the upstream `ReflectionServiceImpl`. `list_services` includes that region's business services and reflection only. File descriptors include complete proto files and dependencies, so a shared file can reveal other symbols; this is not symbol-level access control. Unknown symbols are not resolved from another region's registry. The wrapper uses immutable endpoint metadata and does not create or dispose business service instances.

## Hosting Notes

gRPC normally uses HTTP/2 and Protocol Buffers. Configure Kestrel, TLS, proxies, message limits, deadlines, and compression according to the [ASP.NET Core gRPC guidance](https://learn.microsoft.com/aspnet/core/grpc/). Propagate `ServerCallContext.CancellationToken` through downstream work.

🚨 Server reflection reveals service metadata and is mapped by this package. Restrict access at the network and authorization layers when the deployment must not publish its contract surface.

## Plugin-Based Integration

The host supplies Zongsoft.Core, Zongsoft.Web, Zongsoft.Plugins and Zongsoft.Plugins.Web. Deployment manifests never reference these four libraries; compile-time dependencies remain in the project file.

This package supplies the Web endpoint policy for gRPC: bare `grpc` defaults to `grpc+http2`, requests are classified by native gRPC media types, and the policy enforces method, HTTP version, exact method path and missing-scope response rules. Its implementation is private and registered through `GrpcEndpointExtension.AddGrpcWebEndpoints`; these protocol checks are absent from the Web library.

Explicit hosts call `services.AddGrpcWebEndpoints()` before `AddWebEndpoints` creates the snapshot. Plugin service registration already performs this step automatically. Building gRPC request scopes fails when the extension is missing instead of starting as ordinary HTTP. KestrelUtility can independently convert explicit carriers such as grpc+http2 without this runtime policy; converting bare grpc requires the normalization rule. Plugins.Web service scanning automatically calls AddWebEndpoints for declared Web host endpoints, deferring snapshots to the final provider. Service mapping runs after that snapshot is available; the initializer requires matching declarations for all tagged services. A host with neither business gRPC services nor gRPC declarations needs no reflection routes.

`WebEndpointMetadata("/opentelemetry", "grpc")` associates a route with its scope and request `Kind`; the initializer attaches it to each route group. The independent [test project](test/Zongsoft.Web.Grpc.Tests.csproj) covers protocol rules, regional mounting and real HTTP/2 calls. HTTP/3, reverse-proxy operation and Diagnostics client adaptation have separate validation steps.

Compose this feature through the host; a package reference supplies compile-time APIs, while plugin loading also requires deployed manifests and runtime assets. See [the complete plugin workflow](../../Zongsoft.Plugins/README.md).

Use a Plugins.Web host. The initializer registers gRPC and maps service types tagged `gRPC`; deploy the actual protocol/service plugin as well. HTTP/2 endpoint and reflection exposure remain explicit host decisions.
