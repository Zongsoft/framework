# Expressions 变量求值设计记录

> 状态：第一阶段 Expressions 已实现；正式使用方式见[模板文档](expressions.zh-Hans.md)。更新日期：2026-10-09。
> 本文记录已经确认的第一阶段契约、实现工作及后续阶段事项；历史候选仅供追踪，不作为现行方案。
> 当前只推进第一阶段 Expressions。后续答复应更新本文的决策及待办状态，避免旧方案重新进入实现。

## 目标与阶段

将 tools 仓库 `.shared/VariableEvaluator.cs` 的通用能力提升到 Zongsoft.Core，归属 `Zongsoft.Expressions`。Expressions 提供可独立使用的解析与求值能力；Profile 和工具分别集成。此次明确不考虑旧语法、旧 API 或旧行为的兼容性，不建设兼容模式或旧实现包装层。

| 阶段 | 范围 | 当前状态 |
| --- | --- | --- |
| 1 | Expressions：变量来源抽象、文本插值、成员导航、索引、作用域、格式化，以及未来计算表达式的语法位置。 | 已实现；本次提交范围。 |
| 2 | Profile：显式求值的扩展方法、变量环境绑定、导入应用与保存行为。 | 暂缓，入口重新设计。 |
| 3 | tools：迁移 deployer、packager、migrator、containerizer 的调用与配置模板。 | 第一、二阶段完成后推进。 |

## 已确定的要求

| 编号 | 决策 |
| --- | --- |
| D01 | 不兼容原 `%var%`、`$(var)` 语法，统一采用 `${...}`。旧语法不再具有变量展开含义。 |
| D02 | 本阶段实现变量求值，预留未来轻量表达式；暂不实现算术、条件运算或函数体系。 |
| D03 | 变量、成员和命名空间各段统一采用 ASCII 标识符规则 `[A-Za-z_][A-Za-z0-9_]*`：必须以英文字母或下划线开头，其余字符只能是英文字母、ASCII 数字、下划线。普通文本和字符串索引键不受此限制；名称比较规则见 D24。 |
| D04 | 支持对象成员导航和索引，例如 `${person.Home.Address}`、`${arr[0].Name}`。`.`、`[`、`]` 是语法符号，不是标识符的一部分。 |
| D05 | 支持 `${namespace:var_name}`；命名空间可由多个 `.` 分隔的段组成。 |
| D06 | 支持 `${var#format}`，`#` 右侧为格式字符串，例如 `${x#0.00}`、`${date#yyyy-MM-dd HH:mm:ss}`。 |
| D07 | 变量由调用方提供；需要动态变量来源的公开抽象。Profile 内的配置项不自动成为变量。 |
| D08 | Profile 的 `Value` 保存原文，显式求值，保存时保留表达式，不引入重复的 `RawValue`。 |
| D09 | Profile、ProfileEntry、ProfileDirectiveContext 的求值入口使用扩展方法，不作为实例内置方法。具体签名留待第二阶段。 |
| D10 | `ProfileOptions` 同时增加 `Variables`、`VariableProvider`、`Evaluation` 三个属性的旧草案不定稿；第二阶段重新设计简洁入口。 |
| D11 | 不为方便单元测试扩大类型或成员的可见性；公开抽象必须有生产调用或扩展需要。 |
| D12 | 采用整段模板的反斜杠转义：`\${...}` 输出字面占位符，普通文本中也解释 `\\`、`\n`、`\t`；不采用仅在 `${` 前处理反斜杠的局部方案。完整字符集合、索引字符串及字面边界见 D33—D35，格式字符串另行定义。 |
| D13 | 未来计算表达式只采用 `${=expression}`；不支持 `${(expression)}` 同义入口。表达式内部仍可使用括号分组，本阶段仅预留计算入口。 |
| D14 | 索引同时支持固定常量和动态变量/成员访问，例如 `${arr[0].Name}`、`${settings['display-name']}`、`${arr[index].Name}`、`${settings[user.Key]}`。索引参数中的根变量从变量环境取得，不从被索引对象中查找；本阶段不引入索引内的算术计算。 |
| D15 | 显式命名空间精确查找：`${app.prod:timeout}` 只查询 app.prod，不自动回退到 app 或默认作用域。默认值组合可由提供器显式组织；缺失、null 及异常按 D19—D21、D50—D51 处理。 |
| D16 | 字符串值默认作为字面数据插入；是否递归展开由 TemplateEvaluatorOptions.Recursive 控制。递归能力不依赖调用方逐个包装或标记变量值。 |
| D17 | 变量评估器提供解析前、解析后、格式化前、格式化后四类回调，参考 Profile 指令处理前后的扩展方式，供外部调用方介入处理。通知粒度、接管和改写能力见 D44—D49，失败通知与外部异常见 D50—D51；名称及上下文成员已按 R5 确定。 |
| D18 | 解析后回调位于取值/成员导航之后、递归和格式化之前，取得未格式化的对象值。完整处理顺序为解析前 → 取值与导航 → 解析后 → 可选递归 → 格式化前 → 格式化 → 格式化后 → 插入文本。 |
| D19 | 根变量未定义且未由外部提供替代值时，默认求值失败并报告缺失；不默认保留占位符或替换为空字符串。这不等同于变量已存在但值为 null。 |
| D20 | 成功取得的最终 null 直接交给 .NET 基础类库格式化，Core 不为 null 增加特殊预处理。空字符串是 .NET 默认格式化的结果；解析后及格式化前回调仍取得真实 null，不提前改写。 |
| D21 | 成员链中途遇到 null 而无法继续导航时，求值失败；不自动停止导航并传播 null。例如 person.Home 为 null 时，`${person.Home.Address}` 失败。 |
| D22 | 文本格式化尽量直接复用 `string.Format(...)` 等 .NET 基础设施，将原始值、格式和格式化提供器交给基础类库处理；Core 负责模板语法及回调，不重复实现基础格式化规则。 |
| D23 | 模板评估选项提供可空的文化区域属性，调用方可显式指定 CultureInfo；未指定或为 null 时，不主动指定区域，直接沿用 .NET 基础类库的默认行为。不默认使用 InvariantCulture，也不预先快照 CurrentCulture。 |
| D24 | 命名空间、根变量及对象成员名统一采用 OrdinalIgnoreCase 语义，忽略大小写且不受 Culture 设置影响。字符串索引键仍遵循目标字典或索引器自身规则，评估器不改写键值或替换容器比较器。 |
| D25 | 变量引用采用紧凑写法，不允许语法空白；`${ name }`、`${arr[ index ]}`、`${price #0.00}` 均为语法错误。字符串索引键中的空白属于数据；格式中的空白按 D68 处理。此规则不预先限制未来计算表达式内部的空白。 |
| D26 | 未转义的 `${` 开始后，直到模板结束仍缺少闭合 `}` 时，模板解析失败并报告占位符起始位置；不将未闭合片段作为普通文本返回成功结果。此决定不承诺此前的提供器或回调从未执行，也不代表回滚外部副作用。 |
| D27 | 模板普通文本中，未知转义或末尾单个反斜杠导致解析失败并报告位置；字面反斜杠必须写成 `\\`。此决定不自动规定索引字符串和 .NET 格式字符串的内部转义。 |
| D28 | 字符串索引键同时支持单引号和双引号，两者含义相同。例如 `${settings['name']}` 与 `${settings["name"]}` 都使用字符串键 name；内部转义见 D34。 |
| D29 | 出现格式分隔符 `#` 后必须提供非空格式内容，`${value#}` 为语法错误；不省略 `#` 后的语法校验来套用基础库的空格式行为。按 D68 忽略首尾未受保护空白后仍须非空，因此 `${value# }` 同样为语法错误。 |
| D30 | 索引允许负数常量和动态取得的负数值，交给目标容器处理；不转换为从末尾计数。负数键字典可成功，普通零起点数组的负下标越界失败。 |
| D31 | 支持多参数索引，如 `${matrix[1,2]}`、`${grid[row,column]}`，用于多维数组或接受多个参数的索引器；参数个数必须匹配目标。 |
| D32 | 动态索引参数可包含嵌套索引和显式命名空间，如 `${arr[indices[0]].Name}`、`${arr[app:position].Name}`。复用变量引用的命名空间、成员及索引导航规则；参数内不再包 `${...}`，不开放算术、方法调用或格式化。 |
| D33 | 模板普通文本的转义集合为 `\\`、`\$`、`\n`、`\r`、`\t`、`\'`、`\"`；不支持 `\u`、`\U`、`\x` 等未列出的序列。未知或不完整转义失败，转义产生的字符作为字面数据追加，不再次扫描为插值。 |
| D34 | 字符串索引键复用 D33 的转义集合及未知/不完整转义失败规则；引号内不执行模板插值。`${map['${name}']}` 使用字面键 `${name}`，需要动态键时使用 `${map[name]}`。 |
| D35 | `\${...}` 只转义 `$`，不建立整个字面区域；后续文本继续正常扫描。`\${name` 输出 `${name`；name = Alice 时，`\${a${name}}` 输出 `${aAlice}`。真正未闭合的占位符仍按 D26 失败。 |
| D36 | 格式扫描识别单/双引号及反斜杠保护的字符，只有引号外且未被反斜杠保护的 `}` 才结束占位符。不应用模板字符反转义，也不删除格式中的引号或反斜杠；格式空白按 D68 处理后交给 .NET。 |
| D37 | 未来计算结果沿用 `#format`，保留 `${=expression#format}` 形式，先计算再格式化；第一阶段不实现计算，仅保留此语法位置。 |
| D38 | 第一阶段遇到 `${=...}` 时识别为预留计算入口，报告计算表达式尚不支持并求值失败；不将其作为普通文本保留，也不交给变量来源按名称查询。具体异常类型在 API 设计时确定。 |
| D39 | 变量来源采用直接传入名称和命名空间、通过 TryGetValue 返回是否找到及原始对象值的最小接口。不增加 VariableRequest 等请求上下文类型；当前业务信息由来源实例持有，以后有实际新需求再扩展。 |
| D40 | 用户曾要求解析实现方案待定，并允许修改现有词法分析和成员表达式；最新方向按 D67 采用既有 Lexer。格式空白按已确认的 D68 处理，不删除字符串键或受保护的字面空格。 |
| D41 | 评估器采用实例持有变量来源和默认选项的方式，并提供 Providers 集合，构建实例时可配置多个提供器。Evaluate 使用实例配置；构造接收可选 options，提供器通过集合配置。查找规则见 D43，集合及配置引用见 D57。 |
| D42 | 每次变量引用在正常取值流程中重新查询来源，评估器不缓存根变量值；成员 getter、索引和完整路径结果也不缓存。来源可自行提供缓存或固定数据；模板语法解析结果能否复用属于另一问题。 |
| D43 | 提供器按注册顺序查询，首个 TryGetValue 返回 true 的来源决定根变量值；false 继续下一来源，true + null 仍成功并停止。每次传入相同的名称和命名空间，不执行命名空间回退；全部返回 false 时按缺失变量失败，异常不伪装为 false 继续查找。 |
| D44 | 正常求值时，每个完整变量引用触发一组解析前后回调，不逐个通知成员、索引步骤或提供器尝试。动态索引中的变量引用独立触发嵌套通知；重复引用及递归模板中的引用分别通知，常量索引不增加通知。失败路径按 D50 不触发对应后置通知。 |
| D45 | 解析前回调可提供完整引用的对象值并显式标记已接管，跳过默认来源查询、成员导航及该引用内部的动态索引求值，继续解析后、可选递归及格式化阶段。null 也可作为成功结果；接管不绕过语法校验，未执行的索引引用不产生通知。 |
| D46 | 所有进入文本格式化阶段的插值均触发格式化前回调，成功完成后触发格式化后回调，包括未写 #format、最终值为 null 及解析前已接管的结果。普通模板文本不触发；动态索引引用本身不做参数文本格式化，其字符串递归产生的子模板按 D52 处理。失败路径遵循 D50。 |
| D47 | 解析后回调可替换最终对象值，包括 null；修改后的值继续进入可选递归与格式化，不重新执行来源查询或成员导航。动态索引变量的解析后回调也可修改原始下标值。 |
| D48 | 格式化前回调可调整当前引用的值、格式及文化区域，也可提供文本并显式接管，跳过默认 .NET 格式化，随后仍执行格式化后回调。调整不修改评估器共享选项，不重启取值或递归；解析与格式化的接管分别判断。 |
| D49 | 格式化后回调可替换最终文本，结果直接插入模板，不再次执行取值、递归或格式化。即使启用递归，将结果改成 `${other}` 也只输出该字面文本。 |
| D50 | 后置回调仅在对应阶段成功后触发，前置回调显式接管也算成功。取值失败不执行解析后及后续阶段；格式化失败不执行格式化后；已完成的通知不撤销或重复执行。后置回调不承担失败通知或 finally 清理职责。 |
| D51 | 提供器、getter、索引器、.NET 格式化实现及用户回调抛出的执行异常，以 TemplateEvaluationException 携带引用、模板位置和失败阶段，通过 InnerException 保留原异常，并终止本次求值。不吞掉错误、不因异常尝试下一来源，也不返回部分文本作为成功结果；诊断成员见 D73。 |
| D52 | 动态索引取得的字符串也遵循递归选项：开启时在解析后将字符串作为子模板展开，再将结果字符串用作索引参数；关闭时使用原始字符串。递归阶段本身不做类型转换，非字符串参数保留原始类型；随后索引绑定阶段按 D69 调用 ConvertValue 转为目标参数类型。引号内的常量键仍不插值；递归子模板中的引用正常触发解析和格式化回调。 |
| D53 | 选项提供最大字符串递归展开深度，默认 64，显式设置须为正整数。根模板计第 1 层，每次将字符串值作为子模板评估时加一层，进入超限子模板前失败；同层重复引用不累计深度。动态字符串索引的子模板共享当前深度，不另起计数。 |
| D54 | 首版以最大展开深度终止过长递归，不仅凭活动链中同名或同路径重复就判为循环；允许动态提供器通过重复查询得到不同值并最终结束。超限报告深度限制，不断言必有静态循环。 |
| D55 | 模板 Evaluate 始终返回字符串，即使只有单个无格式引用也正常经过递归和格式化；不根据模板形态隐式切换为原始对象返回值。独立的原始值入口不在此决定中增加。 |
| D56 | 同时提供 TryEvaluate，成功返回 true 和字符串结果，错误输出为空；求值失败返回 false、结果为 null，并输出保留位置、阶段及底层异常的诊断。覆盖语法、缺失、递归超限和来源/回调执行错误；非法调用参数和无效配置仍抛异常。Evaluate 继续抛异常报告失败，两入口共享求值语义，不重复执行或回滚已发生的副作用。 |
| D57 | Providers 与 Options 属性仅有 getter，构造后引用固定，集合内容与选项成员仍可修改。Providers 采用 IList<IVariableProvider> 支持添加、插入、删除及顺序调整；不提供整体替换集合或选项对象的 setter。 |
| D58 | 每次求值直接读取已有集合和选项，不创建调用级配置快照；调用方保证本次求值及其自动递归期间不修改配置，修改在调用之间进行。当前引用的上下文改值、格式或 Culture 仍立即生效，提供器返回的动态数据不因此固定。 |
| D59 | 四类回调采用评估器实例上的 .NET event，通过订阅配置；选项仅保存文化区域、递归等设置，不再同时提供选项委托属性。事件的通知、改写、接管及失败语义遵循已确定规则，事件名与 EventHandler<T> 委托形态按 R5 确定。 |
| D60 | 构造时直接持有传入的选项实例，Options 与该对象为同一引用；省略或传 null 时，为该评估器创建独立默认选项，不使用共享默认实例。构造和求值时均不复制选项；共享同一选项的所有调用方须遵守求值期间不修改配置的约定。 |
| D61 | 前置事件按订阅顺序通知所有处理器，最后检查 Handled 的最终值决定是否跳过默认处理；设置 true 不停止后续通知，后续处理器可调整结果或改回 false。处理器抛异常时立即终止后续通知并按既定规则报告失败；后置事件修改 Handled 不重执行已完成阶段。 |
| D62 | 成员导航仅读取公共实例成员，包括具有公共读取契约的字段、属性及索引器；不开放静态成员、非公共读取或方法调用。公共接口及集合适配需核验，不能直接沿用现有 Reflection 的静态成员和方法查找行为。 |
| D63 | 索引常量除整数和引号字符串外，还支持小数、布尔值和 null。常量不查询变量来源，也不增加动态参数解析事件；数字 CLR 类型、字面量形式及关键字与同名变量的区分继续细化。支持 null 常量不代表目标容器必须接受 null 参数。 |
| D64 | 无后缀整数优先采用 int，超出 int 范围但仍在 long 范围内则采用 long；L/l 后缀显式指定 long，超出 long 范围失败。首版不增加无符号整数或 BigInteger 的专用字面量，动态参数仍可提供这些类型。类型判断须包含负数完整值，正确处理 int.MinValue 和 long.MinValue。 |
| D65 | 无后缀小数默认 double；f/F、d/D、m/M 分别显式指定 float、double、decimal，也允许 1m 等无小数点的后缀形式。数字语法固定使用 `.` 小数点，不受格式化 Culture 影响，`,` 保持索引参数分隔符。其它词法细节按 D67 由统一设施处理。 |

| D68 | 格式字符串仅忽略首尾未被引号或反斜杠保护的空白，保留内部及受保护的空白；处理后为空则按空格式失败。回调主动设置的 Format 直接交给基础库，不再次应用源码空白规则。 |
| D69 | 索引参数按目标参数类型使用 Zongsoft.Common.Convert.ConvertValue(value, targetType) 转换，沿用其既有数值、字符串、null 和转换器语义；不维护模板专用转换规则。精确类型和可直接赋值匹配优先，转换候选仍不能唯一确定时报告歧义；转换方法抛出的异常纳入统一求值诊断。 |
| D70 | 每层模板先完整解析，再从左到右执行。当前层语法失败前不查询来源或触发求值事件；递归子模板取得后再解析，已完成的外部操作不回滚。 |
| D71 | Evaluate(null) 和 TryEvaluate(null, ...) 均抛 ArgumentNullException；空模板成功返回空字符串且不触发变量事件，普通空白文本保留。回调提供的 null 文本直接交给 .NET 拼接，不增加 Core 的特殊替换。 |
| D72 | R5 公开 API 整体确认：TemplateEvaluator、TemplateEvaluatorOptions、IVariableProvider；选项 Culture/Recursive/MaximumDepth；四个 EventHandler<T> 事件及 VariableEvaluationContext/VariableFormattingContext 按下方公开成员表实现，不公开内部语法树、会话或多余基类。 |
| D73 | R6 统一诊断确认：TemplateEvaluationException 同时用于 Evaluate 抛出和 TryEvaluate 错误输出，附加 Code、Stage、Template、Expression、Position、Length、Depth，保留 InnerException。Stage 使用 TemplateEvaluationStage；递归错误定位到实际失败层，首版不增加公开引用链模型。 |

## 第一阶段语法边界

### 示例与解析层次

| 模板 | 预期含义 |
| --- | --- |
| `${name}` | 以默认命名空间 null 按注册顺序查询提供器，取得根变量 name。 |
| `${person.Home.Address}` | 取得 person 对象，再逐级读取 Home、Address。 |
| `${arr[0].Name}` | 取得 arr，读取第 0 个元素，再读取其 Name。 |
| `${app.runtime:person.Home.Address}` | 从 app.runtime 作用域取得 person，再执行成员导航。 |
| `${x#0.00}` | 对 x 的最终值应用数值格式。 |
| `${date#yyyy-MM-dd HH:mm:ss}` | 对日期值应用指定格式；冒号属于格式，内部空格按 D68 保留。 |
| `${app.runtime:arr[0].Price#0.00}` | 作用域、根变量、索引、成员导航、格式化依次组合。 |

外层解析器应先识别作用域、访问路径和格式部分；提供器只负责取得根值，成员读取复用 Reflection，格式化作用于导航完成后的值。不要让每个提供器自行解析整段模板。

以下给出结构语法；转义、索引常量、格式终止符和预留计算入口分别按后续已确认规则处理。变量引用不允许插入语法空白：

```text
插值      := '${' 引用 ['#' 格式] '}'
引用      := [命名空间 ':'] 标识符 访问段*
命名空间  := 标识符 ('.' 标识符)*
访问段    := '.' 标识符 | '[' 索引参数 (',' 索引参数)* ']'
索引参数  := 常量 | 引用
标识符    := (字母 | '_') (字母 | 数字 | '_')*
字母      := 'A'..'Z' | 'a'..'z'
数字      := '0'..'9'
```

### 标识符字符集（Q08：已确定 A，ASCII）

变量、成员和命名空间每段统一采用 `[A-Za-z_][A-Za-z0-9_]*`。该字符集与现有 MemberExpressionParser 一致；名称统一忽略大小写，详见 Q08a。

| 示例 | 结论 |
| --- | --- |
| `${name}`、`${first_name}`、`${_value2}` | 合法 ASCII 标识符。 |
| `${app.runtime:person.Home}` | 命名空间各段、根变量和成员名均合法；点号属于分隔语法。 |
| `${2value}`、`${first-name}` | 非法：不能以数字开头，标识符中不能含连字符。 |
| `${姓名}`、`${café}`、`${业务.订单:person.Name}` | 非法：标识符包含非 ASCII 字母。 |
| `显示名称：${settings['显示名称']}` | 合法：普通文本和引号内的字符串索引键不受标识符字符集限制。 |

### 标识符大小写（Q08a：已确定 A，统一忽略大小写）

命名空间、根变量及对象成员名统一采用 OrdinalIgnoreCase 语义，忽略大小写，不受格式化的 Culture 设置影响。该规则是已确定的语言契约，不由不同变量来源任意改变。

实现时应在变量来源抽象及适配器中落实这一契约，不能仅将传入名称转小写就假定任意来源都能正确查找。复用 Reflection 时仍需验证成员查找及歧义行为，不能因其默认忽略大小写就省略检查。API 与歧义处理按已确认的 R2、R5、R6 实现。

假设 app.runtime 中注册变量 person，其对象有 Name 属性且值为 Alice：

| 模板 | 结果 |
| --- | --- |
| `${app.runtime:person.Name}` | Alice。 |
| `${APP.RUNTIME:person.Name}` | Alice。 |
| `${app.runtime:Person.Name}` | Alice。 |
| `${app.runtime:person.name}` | Alice。 |

字符串索引键是数据，仍交给被索引的字典或索引器处理。`${settings['Name']}` 与 `${settings['name']}` 是否访问同一项，由 settings 自身的比较规则决定；评估器不重写键值或替换容器的比较器。

### 引用中的语法空白（Q08b：已确定 B，紧凑写法）

变量引用不允许语法单元之间出现空白，包括空格、Tab 和实际换行（按 char.IsWhiteSpace 分类）。不能通过 Trim 或先删除空白使非法引用变成合法引用；也不能拆开 `${`、标识符或数字常量。

此限制只针对变量引用语法，不限制模板普通文本中的空白，也不预先规定未来 `${=expression}` 内部的空白规则。

| 示例 | 结论 |
| --- | --- |
| `${name}`、`${app.runtime:person.Name}`、`${arr[index].Name}` | 合法。 |
| `${ name }` | 语法错误。 |
| `${ app.runtime : person . Name }` | 语法错误。 |
| `${ arr [ index ] . Name }`、`${arr[ index ]}` | 语法错误。 |
| `${first name}` | 语法错误，不能拼成 firstName 或 firstname。 |
| `${price #0.00}` | 语法错误，`#` 之前不能有语法空白。 |
| `${settings['display name']}` | 合法，空格属于字符串键。 |
| `${date#yyyy-MM-dd HH:mm:ss}` | 空格位于格式内部，按 D68 保留，不是变量引用的语法空白。 |
| `${price#0.00 }` | 格式中的末尾空格允许考虑忽略；不再假定必定进入最终格式。 |

字符串索引键中的空白继续作为数据保留；格式空白按 D68 处理。变量引用本身仍要求紧凑写法。现有 MemberExpressionParser 接受语法空白，在 Lexer/引用语法改造中落实紧凑约束，共享行为的变化需检查直接下游。

### 未闭合的占位符（Q08c：已确定 A，解析失败）

未转义的 `${` 开始后，直到模板结束仍缺少闭合 `}` 时，模板解析失败并报告未闭合占位符及起始位置，调用方不取得成功的文本结果。不将剩余片段作为普通文本保留。

这一规则针对真正的占位符起始标记；Q01d 已确认 `\${` 只转义美元符，因此 `\${name` 不属于未闭合占位符，输出字面 `${name`。

假设 name = Alice：

| 模板 | 结果 |
| --- | --- |
| `目录：${root` | 解析失败，报告 `${root` 的起始位置。 |
| `用户：${name}；目录：${root` | 解析失败，不返回 `用户：Alice；目录：${root` 作为成功结果。 |

是否先解析完整模板再调用提供器/回调属于执行时机，不能仅由“失败时没有成功文本结果”推出回调从未执行或具有回滚能力。具体异常类型及 Try API 留待接口设计。

### 索引与字面参数

Q03 已选择 B：固定常量和动态变量/成员访问均可作为索引参数。以下是已确认的使用形态：

```text
${settings['display-name']}
${arr[index]}
${settings[key]}
${arr[selection.Index].Name}
```

字符串索引中的 `display-name` 是键的字面值，不是变量标识符；变量名的限制不应误套到键内容上。

负数、多参数及动态参数的组合能力已在 Q03b、Q03c、Q03d 确定支持；字符串内部转义见已确定的 Q01c，常量范围见已确定的 Q03e，数字类型和字面量规则继续细化。`${arr[1 + 2]}` 这样的计算留到未来表达式阶段。数组、列表、字典、对象索引器需要分别验证，不能仅凭语法示例认为底层已经支持。

Q03a（已确定 A）：字符串索引键同时支持单引号和双引号。

两者语义相同，`${settings['name']}` 与 `${settings["name"]}` 都使用字符串键 name。包含单引号的键可写成 `${settings["user's name"]}`，包含双引号的键可用单引号包裹。使用哪种引号不改变字符串键的大小写匹配规则。

索引字符串的完整字符转义表及不执行引号内插值的规则已在 Q01c 确定。

下列示例假设 arr 的两项 Name 分别为 Alice、Bob，index = 1，key = 'display-name'，settings['display-name'] = 'Alice'。

| 场景 | 模板 | 结果/语义 |
| --- | --- | --- |
| 固定数组下标 | `${arr[0].Name}` | Alice。 |
| 固定字典键 | `${settings['display-name']}` | Alice；键内容不受标识符字符限制。 |
| 变量下标 | `${arr[index].Name}` | Bob；index 来自变量环境，不是 arr 的成员。 |
| 变量字典键 | `${settings[key]}` | 以 key 的值作为键，结果为 Alice。 |
| 成员决定下标 | `${arr[selection.Index].Name}` | 从变量 selection 的成员取得下标。 |

动态索引参数复用变量来源及成员访问能力，不能将 arr 作为 index 或 selection 的变量环境。参数内允许显式命名空间和嵌套索引，见 Q03d；不因此开放全部 Reflection 语法。

以下三个索引边界均已选择 A：

| 编号 | 示例 | 已确定行为 |
| --- | --- | --- |
| Q03b | `${map[-1]}`；index = -1 时的 `${map[index]}`。 | 允许，将负数直接交给目标容器。不解释为“倒数第一项”；负数键字典可成功，普通零起点数组越界时失败。 |
| Q03c | `${matrix[1,2]}`、`${grid[row,column]}`。 | 支持多维数组及实际接受多个参数的索引器；参数个数须匹配目标容器。 |
| Q03d | `${arr[indices[0]].Name}`、`${arr[app:position].Name}`。 | 支持，先求得参数的值再读取 arr；不需要在参数内再包 `${...}`。 |

这些能力可以组合，例如 `${matrix[indices[0],app:column].Name}`。引用内部仍要求紧凑写法，`${matrix[1, 2]}` 因语法空白而非法。此决定仅组合取值能力，不开放索引内算术、方法调用或格式化；显式命名空间仍精确查找，无命名空间的根变量仍从默认变量环境取得。实现时需验证嵌套解析和求值，不能仅凭复用语法就假定 Reflection 已完整支持。

Q13 已确定第一阶段拒绝方法调用节点，`${person.GetAddress()}` 不合法。未来计算表达式是否开放调用需要另行设计；现有解析器支持方法节点不改变这一限制。

### 索引常量的类型范围（Q03e：已确定 B）

索引参数支持整数、引号字符串、小数、布尔值和 null 常量，同时保留动态变量/成员参数。类型范围由语言契约确定，不由是否使用现有 Lexer 自动决定。

| 示例 | 已确定语义 |
| --- | --- |
| `${map[1.5]}` | 以 double 常量作为参数；decimal 可写成 `${map[1.5m]}`。 |
| `${flags[true]}` | 以布尔常量 true 作为参数，不查询名为 true 的来源变量。 |
| `${map[null]}` | 以 null 作为参数；是否接受由目标容器及参数匹配规则决定。 |
| `${flags['true']}` | 仍是字符串键，与布尔常量不同。 |
| `${map[key]}` | key 由变量环境提供，保留其对象类型；动态参数不局限于常量语法可直接表示的类型。 |

常量本身不查询来源，也不触发动态参数解析事件。支持 null 常量不能推出字典必须接受 null 键；绑定时先按 R2 转换。整数及小数默认类型已在 Q03f、Q03g 确定；数字词法由既有 Lexer 统一处理，索引参数匹配和转换按 R2 实现，不引入算术运算。

### 数字常量的默认类型（Q03f、Q03g：均已确定 A）

索引参数以对象传递，数值相同不代表 CLR 类型相同。例如接受 object 键的容器可以区分 int 的 1 和 long 的 1，以及 double 的 1.5 和 decimal 的 1.5。常量解析的默认类型固定；目标参数类型确定后，再按 R2 使用 ConvertValue 转换。目标类型为 object 时该方法保留原始值。

Q03f：无后缀整数优先 int，超出 int 范围但仍在 long 范围内则使用 long；L/l 显式指定 long，超出 long 范围失败。首版不增加无符号整数或 BigInteger 的专用字面量，但动态参数可提供这些类型。

| 常量 | CLR 类型或结果 |
| --- | --- |
| `1`、`2147483647` | int。 |
| `2147483648` | long。 |
| `1L`、`1l` | long。 |
| `-2147483648` | int，包含最小值。 |
| `-9223372036854775808` | long，包含最小值。 |
| `9223372036854775808` | 超出 long 范围，失败。 |

负号属于整数常量的完整值，类型及范围判断须覆盖 int.MinValue 和 long.MinValue，不先用相应正数类型解析其绝对值而误报溢出。

Q03g：带小数点的无后缀数值默认 double。f/F、d/D、m/M 分别显式指定 float、double、decimal，例如 `1.5f`、`1.5d`、`1.5m`；也允许用这些后缀标注无小数点的数值，如 `1m`。

`1.5` 与 `1.5d` 同类型；需要明确产生 decimal 常量时写 `1.5m`。这些是字面量解析阶段的类型；后续索引绑定按 R2 调用 ConvertValue，能否转换及具体结果遵循该方法。

数字语法使用固定的 `.` 小数点，不受格式化选项 Culture 影响；`,` 保持多参数分隔符。`${grid[1,5]}` 始终表示两个参数，不因文化区域变化而变为小数 1.5。格式化选项未指定/null 时仍按 D23 保持 .NET 默认，这与解析固定语法没有冲突。

其余数字写法以既有 NumberTokenizer 的能力为基础统一整理，按已定类型、负数和范围规则补齐；不再逐项询问科学计数法、简写或溢出边界。当前实现不支持的可选写法不因先前候选示例就自动纳入首版；内部不一致或错误行为需要修正并记录。未来计算表达式共享同一词法设施，不另造同义但不同规则的数字解析。

### 布尔/null 关键字与变量名称（Q03h：已确定 A）

仅在完整索引参数为裸 true、false、null 时识别为常量，其它变量、成员及命名空间位置仍按标识符处理。按 OrdinalIgnoreCase 识别完整关键字，true、TRUE、True 同义；trueValue 不匹配关键字前缀，字符串键不受关键字规则影响。

| 模板 | 含义 |
| --- | --- |
| `${map[true]}`、`${map[TRUE]}` | 布尔常量参数，不查询提供器。 |
| `${map[null]}` | null 常量参数，不查询提供器。 |
| `${true}` | 查询根变量 true。 |
| `${map[app:true]}` | 查询 app 命名空间的 true 作为索引参数。 |
| `${map[true.Code]}` | 查询变量 true 的 Code 作为索引参数。 |
| `${person.True}` | 读取成员 True。 |
| `${true:person}` | 从命名空间 true 查询 person。 |
| `${map[trueValue]}` | 查询完整变量名 trueValue。 |
| `${map['true']}` | 使用字符串键 true。 |

需要默认作用域中名为 true 的变量作为裸索引参数时，可使用其它变量名，或由明确的命名空间暴露该值，不增加反引号等新转义语法。未来 `${=true}` 作为计算分支可以具有布尔常量语义，不应悄悄改变已定稿的普通 `${true}` 或索引引用含义。

### 数字词法的统一处理（Q03i、Q03j：撤回独立问答）

用户指出采用 Expressions 现有词法分析器后，不应继续将这些细节逐一交给调用方选择。当前采用 D67 路线：复用并完善 NumberTokenizer 等现有设施，统一处理后缀、数值范围、token 边界和错误位置。Q03i、Q03j 的 A/B 候选仅为此前草拟问题，不是已接受的语法。

已确定的 int→long、double 默认值、大小写不敏感后缀、固定小数点和负数语义必须落实；现有实现的缺陷不能视为用户选择。其它数值写法不为模板另建规则，未有明确需求的扩展不作为首版必要能力。索引参数匹配属于执行语义，集中列入 R2，不能仅凭复用 Lexer 推导它允许自动类型转换。

### 成员导航范围（Q13：已确定 A，仅公共实例成员）

普通对象导航仅读取公共实例成员，不开放静态成员、非公共读取和方法调用。例如 Person 定义公共实例 Name = Alice，并有公共静态 DefaultName = Guest：`${person.Name}` 得到 Alice，`${person.DefaultName}` 成员查找失败。

属性必须具有可用的公共读取契约；只有公共 setter、没有公共 getter 不等于可读。公共接口暴露的读取契约及集合索引仍需在 Reflection 适配中核验，不能简单把字段/属性的 CLR 元数据可见性作为完整适配规则。

现有 MemberExpressionEvaluator.GetMember 和 Reflector 的名称查找包含 BindingFlags.Public、Instance、Static、IgnoreCase，不能直接作为新语言的成员范围。当前源码还包含方法查找、首个匹配即返回和 Type 特殊处理；这些实现细节不成为语言契约。同名歧义、参数匹配及 Type 对象的普通实例导航需在适配设计中核验，不经 Type 特殊分支重新开放被排除的静态成员。

### 命名空间（Q04：已确定 A，精确查找）

`${app.runtime:person.Name}` 应明确拆成命名空间 app.runtime、根变量 person、访问路径 Name。

多级命名空间用于明确定位，不自动建立继承或回退关系。app.runtime 中找不到 person 时，表达式引擎不查询 app 或默认作用域。

例如 app.prod 未定义 timeout，app 定义 timeout = 30，默认作用域定义 timeout = 10：

| 模板 | 查找范围 | 结果 |
| --- | --- | --- |
| `${app.prod:timeout}` | 只查询 app.prod。 | 未找到，按后续确定的变量缺失规则处理。 |
| `${app:timeout}` | 只查询 app。 | 30。 |
| `${timeout}` | 查询调用方绑定的默认作用域。 | 本例为 10；向 Providers 传入 null 命名空间。 |

需要默认值与覆盖值组合时，由提供器显式组织其内部来源。该决定不同时确定 null 值、成员缺失或索引失败的处理。

默认作用域以 null 命名空间传给提供器；同一作用域允许多个来源，按注册顺序首个成功者生效，详见 Q09d。命名空间与根变量名分别传给来源抽象，避免自定义提供器再次拆解字符串；接口形态见 Q09a。

### 格式化（Q07：区域属性可显式设置，null 保留 .NET 默认行为）

数值和日期应保留原始类型直到最终格式化，不能由提供器先统一转换为字符串。

用户明确要求尽量交给 .NET 基础类库格式化，不为 null 或普通对象重复实现特殊预处理。应将原始值、格式和格式化提供器交给 `string.Format(...)` 等标准入口，遵循基础类库的格式化与扩展规则；不要先统一调用 ToString 或把 null 改为空字符串。

Q07 已确定：模板评估选项提供文化区域属性。调用方显式指定时，将该区域用于格式化；未设置或为 null 时，直接把区域选择交给 .NET 基础类库，不由 Core 设置默认区域或预先快照当前区域。

属性确定为 TemplateEvaluatorOptions.Culture，类型为 CultureInfo。不要将未配置的 null 改写为 CultureInfo.CurrentCulture 或 CultureInfo.InvariantCulture 后保存。

假设 price 为数值 1234.5，模板为 `${price#0.00}`：

| 选项中的文化区域 | en-US 当前区域 | de-DE 当前区域 |
| --- | --- | --- |
| 未设置或 null。 | `1234.50` | `1234,50` |
| 显式指定 InvariantCulture。 | `1234.50` | `1234.50` |
| 显式指定 de-DE。 | `1234,50` | `1234,50` |

这样调用方既可保留 .NET 默认行为，也能在生成固定格式配置或文件时显式选择区域。对 null 的默认格式化及数值示例已通过本地 .NET 格式化调用核验；这不替代后续实现测试。格式字符串边界见 Q07b，格式化入口和回调按已确认的公开 API 实现。

外层只识别路径之后的格式分隔符，不能简单对全部文本执行 Split('#')、Split(':') 或查找第一个 `}`：

```text
${x#0.##}
${date#yyyy-MM-dd HH:mm:ss}
${map['a#b']}
${map['a}b']}
```

前两例中的第二个 `#` 和冒号属于格式，内部空格按 D68 保留。后两例说明字符串索引键中的分隔字符不能被外层误识别，需要按引号边界解析。

格式内部可能有 .NET 自身的反斜杠或引号语义，模板外层不得先全局反转义而损坏它们。格式字符串中的空白按 D68 处理；空格式见 Q07a；格式中的字面 `}` 见已确定的 Q07b，未来表达式结果沿用 `#format`，见 Q02a。

Q07a（已确定 B）：不允许 `${value#}` 这样的空格式字符串。

写出 `#` 后必须提供非空格式，否则为模板语法错误；没有格式需求时省略 `#`。这属于模板语法校验，不改变合法格式交给 .NET 处理的原则。

例如 n 为整数 42，`${n}` 默认输出 `42`，`${n#}` 为语法错误。`${n# }` 忽略首尾空白后格式为空，同样拒绝；原先必然接受只含空白格式的结论已撤回。

Q07c 已随 R1 确认：仅忽略格式首尾未被引号或反斜杠保护的空白，保留内部及受保护空白；处理后为空则按空格式失败。具体示例见集中确认记录。

Q07b（已确定 A）：格式扫描识别引号和反斜杠保护，以确定占位符结束位置。

只有引号外且未被反斜杠保护的 `}` 才结束占位符。不应用 D33 的字符反转义，也不删除用于格式化的引号或反斜杠；格式空白按 D68 处理。这里的扫描用于识别模板边界，实际格式含义仍由 .NET 格式化入口及目标值决定。

假设 amount = 12.3，显式使用 InvariantCulture，`${amount#0.00'}'}` 和 `${amount#0.00\}}` 都预期输出 `12.30}`；两者的原始格式分别为 `0.00'}'` 和 `0.00\}`。也可以用 `${amount#0.00}}` 将字面 `}` 放在占位符外，普通文本中的独立右括号无需转义。

2026-10-09 已通过本地 decimal.ToString(format, InvariantCulture) 核验上述两种格式均输出 `12.30}`。这仅验证基础库的数值格式，不代表新模板解析器已经实现。实现时应采用能接收原始格式的 .NET 格式化入口；不能直接把含大括号的格式拼接为复合格式串，再假定 string.Format 的外层括号语法不会干扰它。

## Q01：反斜杠转义范围（已确定：B，整段模板转义）

以下都是模板的实际字符，不是 C#、JSON 或 shell 字符串源码。宿主语言或文件格式自身的转义属于另一层。示例设 name = Alice。

在所有普通文本中解释 `\\`、`\n`、`\t` 等，并识别插值；`\${...}` 输出字面文本 `${...}`。实现时必须保留转义状态，不能先对全文反转义再无条件重新扫描 `${...}`，否则被转义的字面标记会再次执行。

紧邻 `${` 的连续反斜杠同样按成对转义处理；区别在于其他位置的反斜杠也参与转义。

| 模板输入 | 结果 |
| --- | --- |
| `${name}` | `Alice` |
| `\${name}` | `${name}` |
| `\\${name}` | `\Alice` |
| `\\\${name}` | `\${name}` |
| `first\nsecond` | first、second 分别位于两行。 |
| `a\tb` | a 和 b 之间为一个 Tab。 |
| `C:\\temp\\logs` | `C:\temp\logs` |
| `\\\\server\\share` | `\\server\share` |
| `C:\\apps\\${name}` | `C:\apps\Alice` |

普通 Windows 路径必须按模板规则转义。例如模板中的 `C:\temp` 会把 `\t` 解释为 Tab；需要保留路径时，应写成 `C:\\temp`。此前局部方案保持普通路径不变的示例已撤回。

完整转义表见已确定的 Q01b，索引字符串转义见 Q01c；未知转义（如 `\q`）和末尾单个反斜杠的处理见已确定的 Q01a。不接受 C# 或现有解析器中未在此列出的其它转义。

Q01d 已确认被转义的起始标记只转义美元符；不构造需配对的字面区域，后续新的起始标记正常求值。递归展开返回的字面结果如何避免再次解释仍需在执行模型中落实。

索引字符串已确定复用外层字符转义表，但不执行插值；格式字符串不应用这套转义表，其边界见 Q07b。

### 未知或不完整的外层转义（Q01a：已确定 A，解析失败）

整段模板已经确定解释反斜杠转义。本问题只讨论普通文本中的未知转义和模板末尾不完整的转义；不改变已经支持的 `\\`、`\n`、`\t`、`\${...}`，也不把外层规则直接套到索引字符串和 .NET 格式字符串上。

遇到未定义的转义或末尾单个反斜杠时解析失败并报告位置。需要字面反斜杠时写成 `\\`；不将未知转义原样保留，也不删除反斜杠来隐式修正。这样能发现拼写错误，并为以后增加转义保留空间，避免已成功接受的字面文本在未来被重新解释。

下表展示模板的实际字符，不是 C# 字符串源码；假设 `\q` 不在支持列表中：

| 模板输入 | 结果 |
| --- | --- |
| `text\q` | 未定义的转义，解析失败并报告位置。 |
| `text\` | 不完整的转义，解析失败并报告位置。 |
| `text\\q` | 输出 `text\q`；这是合法的反斜杠转义。 |

完整转义表已在 Q01b 确定；不接受 C# 的其它转义，也不采用“遇到未知转义就删除反斜杠”的隐式行为。

### 转义集合与字面边界（Q01b、Q01c、Q01d：均已确定 A）

Q01b：模板普通文本仅支持以下基本字符转义：

| 写法 | 结果 |
| --- | --- |
| `\\` | 一个反斜杠。 |
| `\$` | 美元符。 |
| `\n` | 换行 LF。 |
| `\r` | 回车 CR。 |
| `\t` | Tab。 |
| `\'` | 单引号。 |
| `\"` | 双引号。 |

未列出的序列（包括 `\u`、`\U`、`\x`）按 D27 报错。转义产生的字符作为字面数据追加，不能再次扫描为插值起始标记；格式字符串不套用这份外层转义表。

Q01c：字符串索引键使用 Q01b 同一字符转义表，未知或不完整转义报错。例如 `${map['a\tb']}` 使用含真实 Tab 的键；`${map['it\'s']}` 使用键 it's。

字符串索引参数始终是字面字符串，不在引号内执行模板插值。例如 `${map['${name}']}` 使用字面键 `${name}`；需要动态键时使用 `${map[name]}`。

Q01d：`\${...}` 只转义 `$`；后续字符继续按普通模板扫描，不要求为这个被转义的起始标记寻找闭合 `}`，不建立整段字面区域。假设 name = Alice：

| 模板输入 | 结果 |
| --- | --- |
| `\${name}` | `${name}`。 |
| `\${name` | `${name`，被转义的美元符未开始真正的占位符。 |
| `\${a${name}}` | `${aAlice}`，后面的独立占位符正常求值。 |
| `\${a\${name}}` | `${a${name}}`，两个美元符均被转义。 |

这一规则不改变 D26 对真正未闭合占位符的失败处理，也不使后续 `\n` 等转义失效。Reflection 的字符串解析若接受额外转义，不能直接将其默认行为当作新模板的规则。

## Q02：未来计算表达式的入口（已确定：A，仅等号前缀）

用户确定只采用 `${=expression}`，不提供 `${(expression)}` 别名。第一阶段只预留入口，不实现计算；识别预留形式后报告计算表达式尚不支持并求值失败，具体诊断类型留待错误处理设计。

例如 price = 12.5、quantity = 2、fee = 1.5，未来实现计算后：

| 场景 | 已确定的写法 | 结果 |
| --- | --- | --- |
| 简单计算 | `${=price * quantity}` | 25 |
| 表达式自身有分组 | `${=(price + fee) * quantity}` | 28 |

`${price}` 查询变量，`${=...}` 标记计算；只保留等号不会限制表达式内部使用括号。圆括号候选仅作为已撤回的讨论记录，不作为合法入口的实现依据。

本次不定义算术优先级、函数注册或类型提升规则。未来增加计算时，变量引用、作用域、成员访问、索引和格式化的既定含义不应被重新解释。

以下两项均已选择 A：

- Q02a：未来计算结果沿用 `#format`，保留 `${=price*quantity#0.00}`，计算完成后格式化结果。这里只确认保留位置，不提前实现计算或完整表达式词法。
- Q02b：第一阶段遇到 `${=1+2}` 时，识别预留入口后报告计算表达式尚不支持，求值失败。不原样保留，不把 `=1+2` 当成变量名交给提供器；异常使用 TemplateEvaluationException，Code 为 UnsupportedExpression。

## 来源抽象、递归与执行模型

### 动态变量来源

动态来源抽象及其最小输入形态已确定，见 Q09a。接口表达命名空间、根变量名称、找到与未找到，以及原始对象值。返回 null 和未找到必须能够区分。

此前 `TryGetValue(string name, out VariableValue value)` 的草案未覆盖显式命名空间，不再采用。递归由评估器选项控制，不为字符串的模板/字面区分强制引入 VariableValue 包装；采用直接传名称和命名空间、返回 bool 与 object 的来源接口形态。

普通字典适配器、动态业务对象提供器和组合来源是实际使用场景；进程环境变量、.env 文件读取和命令行优先级仍由调用方决定。

### 变量来源接口形态（Q09a：已确定 A，最小接口）

提供器只按命名空间和名称返回根变量，成员导航、索引、递归及格式化由评估器组织；不将整段模板交给每个来源解析。用户已选择直接传参，并明确以后有新需求再扩展；不创建独立请求上下文类型。以下是已选择的接口形态，名称及参数顺序仍随最终 API 一并核定。

直接传入名称和命名空间：

```csharp
public interface IVariableProvider
{
	bool TryGetValue(string name, string @namespace, out object value);
}
```

以 null 表示默认命名空间；明确的多级命名空间作为完整字符串传入，不执行隐式父级回退。true + null 表示已找到空值，false 表示未找到。来源自身的异常不应伪装为 false。调用方可用来源实例、构造参数或组合提供器持有文件目录、租户等业务上下文。

不为尚未发生的需求增加请求上下文类型或通用上下文属性，也不把内部求值会话暴露给提供器。

例如 `${app.runtime:person.Home.Address}` 的来源查询只携带 name = person、namespace = app.runtime；得到 person 后由评估器访问 Home.Address。`${arr[indices[0]].Name}` 分别查询根变量 arr 与 indices，索引和 Name 导航也由评估器完成。来源实现须落实 D24 的忽略大小写契约，并支持区分不存在和最终 null；每次引用重新查询的规则见 Q09c，多来源按注册顺序查询的规则见 Q09d。

现有 IExpressionEvaluator 带有脚本求值、全局变量和释放契约；不强制模板评估器套用该接口，也不让变量来源实现同样的生命周期或流选项。公开形态见已确认的 API 汇总。

### 评估器实例与来源集合（Q09b：已确定 B，并增加提供器集合）

用户选择构建实例时配置来源和默认选项，并明确评估器应具有 provider 集合属性。由实例持有配置，随后通过 Evaluate(text) 评估；不将设计限制为绑定单个提供器。

评估器名称确定为 TemplateEvaluator，Providers 采用 IList<IVariableProvider>，Providers 和 Options 仅有 getter，集合内容及选项成员可修改，见 Q09g。构造只接受可选 options，提供器由集合注册，不采用此前的单来源构造示例。

评估时直接读取配置，不建立调用级快照，调用方保证求值及其自动递归期间配置稳定，见 Q09h。每次引用重新查询、不缓存值的行为已经在 Q09c 确定；不为了同时容纳所有调用习惯增加多组平行配置入口。

### 最小入口与配置（已确认）

评估器实例持有来源集合及默认选项，并提供 Evaluate 和 TryEvaluate；Providers 和 Options 引用固定、内容可修改。以下名称和签名已随 R5、R6 确认。

| 位置 | API | 状态 |
| --- | --- | --- |
| 评估器 | TemplateEvaluator。 | 名称与实例使用形态已确定。 |
| 来源集合 | IList&lt;IVariableProvider&gt; Providers { get; }。 | 已确定有序集合接口、仅 getter 及内容可修改，见 Q09g。 |
| 默认选项 | TemplateEvaluatorOptions Options { get; }。 | 已确定仅 getter、直接持有传入对象、选项成员可修改。 |
| 抛异常入口 | string Evaluate(string text)。 | 返回字符串及求值失败抛异常已确定。 |
| Try 入口 | bool TryEvaluate(string text, out string result, out TemplateEvaluationException error)。 | 已确定复用统一求值异常承载错误，不增加平行诊断类型。 |
| 选项内容 | Culture、Recursive、MaximumDepth。 | 对应能力、默认值和名称已确定；选项不包含回调。 |
| 实例事件 | Resolving、Resolved、Formatting、Formatted。 | 已确定采用 EventHandler<T>，具体上下文见公开 API 汇总。 |

构造时可传选项并直接持有，省略或传 null 时创建独立默认选项；提供器通过集合配置，不增加隐式的全局提供器或环境变量来源。使用示例：

```csharp
var evaluator = new TemplateEvaluator(new TemplateEvaluatorOptions
{
	Recursive = true,
	MaximumDepth = 64,
});

evaluator.Providers.Add(runtimeProvider);
evaluator.Providers.Add(defaultsProvider);

var text = evaluator.Evaluate("姓名：${person.Name}");
```

### 配置属性的修改方式（Q09g：已确定 A，固定引用、内容可修改）

Providers 和 Options 属性只有 getter，构造后引用固定；集合内容和选项成员仍可修改。Providers 采用 IList&lt;IVariableProvider&gt; 形态，支持 Add、Insert、Remove、Clear 及顺序调整，不另造只为存储服务的公开集合类型。内部实现及必要的元素校验另按最终契约落实。

允许 evaluator.Providers.Add(provider)、evaluator.Providers.Insert(0, provider) 和 evaluator.Options.Culture = culture；不允许 evaluator.Providers = anotherList 或 evaluator.Options = anotherOptions。修改时机遵循 Q09h，不表示集合内容或选项全部不可变。

### 单次求值的配置读取时机（Q09h：已确定 B，直接读取且调用期间配置不变）

不创建每次调用的配置快照，由调用方保证一次 Evaluate/TryEvaluate 及其自动递归期间不修改配置；评估器直接读取已有集合和选项。集合增删或调整顺序、选项成员修改和事件订阅调整应在求值调用之间进行，不支持在回调中修改评估器配置来影响本次或安排下一次。

例如第一次格式化回调不能通过修改 evaluator.Options.Culture 来影响后续引用；应等 Evaluate 返回后再改配置。若仅需改变当前引用的 Culture、值或格式，使用当前回调上下文已有的可写成员即可，仍按 D48 立即生效。这两个修改对象不能混为一谈。

Culture 为 null 时保持 null，不捕获 CurrentCulture；每次 .NET 格式化仍按其默认规则处理。配置稳定不等于固定来源数据或缓存变量值，提供器仍可按 D42 返回动态数据。本决定不引入集合锁或配置冻结机制，也不额外承诺来源及回调的并发语义。

### 构造时传入选项的持有方式（Q09i：已确定 A，直接持有）

直接持有传入的选项实例，evaluator.Options 与传入对象为同一引用；省略或传 null 时，为该评估器创建独立的默认选项。Options 的引用不能整体替换，构造和每次求值均不复制配置，调用期间遵循 Q09h 的配置不变约定。

例如 options.Recursive 初始为 false，创建 evaluator 后，在尚未求值时将 options.Recursive 设为 true，评估器随之启用递归。允许多个评估器显式共用同一个选项对象，也要求所有共享者求值期间都不修改该对象；省略选项时不使用全局共享默认实例。

事件订阅属于评估器实例，两个评估器共享 Options 不会因此共享订阅。这里的持有不转移外部对象的释放责任，是否需要其它生命周期能力仍按实际生产用途设计。

### 多个提供器的查找规则（Q09d：已确定 A，按注册顺序首个成功者生效）

提供器按注册顺序依次查询，首个返回 true 的提供器决定根变量值。每个提供器都收到相同的变量名和命名空间，不处理该作用域或未找到变量时返回 false。下列注册写法仍为示意，不预先固定集合类型：

```csharp
evaluator.Providers.Add(runtimeProvider);
evaluator.Providers.Add(defaultsProvider);
```

例如 `${app:timeout}` 先询问 runtimeProvider 的 app/timeout，未找到则询问 defaultsProvider 的 app/timeout。同名值优先采用靠前来源；不改变命名空间，不回退到父级或默认作用域。因此不会违反 D15 的精确命名空间规则。

true + null 是成功找到空值，不因 null 改查其它来源。取得根变量后，后续成员导航失败也不触发重新查找根变量；来源顺序用于选择根值，不用于尝试不同对象直到整个路径成功。全部来源返回 false 时遵循默认缺失失败规则。提供器抛出异常不应当作 false 吞掉继续查找，按 D51 包装。

### 对象导航与字符串递归（Q05：已确定 B，递归由选项控制）

`${person.Home.Address}` 是读取对象图；若变量 template 的字符串值本身为 `${person.Name}`，展开 `${template}` 则属于字符串递归求值。

用户确定默认不再解释提供器或成员导航得到的字符串，由 TemplateEvaluatorOptions.Recursive 启用递归展开；默认 false。

示例中的值均为运行时实际字符，不是 C# 字符串源码：

```text
root = /srv
folder = ${root}/config
path = C:\temp
```

| 评估器选项 | 求值 `目录：${folder}` | 求值 `${path}` |
| --- | --- | --- |
| 递归关闭（默认）。 | `目录：${root}/config` | 原样输出 `C:\temp`。 |
| 递归开启。 | `目录：/srv/config` | path 作为下一层模板，其 `\t` 按全局模板转义成为 Tab。 |

模板输入自身始终遵守 Q01 的全局转义规则；递归选项决定变量结果是否作为下一层模板解析，不影响外层模板自身的转义。开启递归时，调用方应按模板规则准备字符串值。

解析后回调调整的值进入可选递归阶段，然后再格式化。格式化前的改值或接管不重启递归；默认格式化、格式化接管及格式化后回调产生的文本均不重新送回递归解析。动态字符串索引同样在解析后按选项递归，见 Q05h；深度上限和重复引用处理见 Q10a、Q10b，各阶段接管规则见 Q05c、Q05f。

同一引用重新求值可能得到不同结果，活动链中再次出现相同路径也不必然无法终止。首版不以引用身份去重或提前判循环；每次正常引用仍查询来源，以已确定的最大深度限制过长展开。

### 动态索引的字符串值递归展开（Q05h：已确定 B，遵循递归选项）

动态索引值为字符串时，也按递归选项展开，再将所得字符串作为参数；非字符串值保留原始类型。索引引用先取得值并执行解析后回调，再执行可选递归，因此解析前接管及解析后改写得到的字符串也适用。以下表示运行时数据，不是 C# 字符串源码：

```text
key = ${name}
name = Alice
map 中有两个不同的键：${name} 和 Alice
模板：${map[key]}
```

上述模板在开启递归时使用键 Alice，关闭时使用字面键 `${name}`。递归阶段产出仍为字符串，随后按目标索引参数类型调用 ConvertValue。若展开结果是 `"1"` 且目标参数为 int，绑定阶段可以转换为 1；这不改变递归阶段的字符串结果或事件粒度。取得 map 的目标值后，外层插值继续按递归选项处理该值。

`${map['${name}']}` 始终按 D34 使用字面键 `${name}`，与递归选项无关。对取得的字符串展开不等于统一格式化所有索引参数；索引引用 key 本身不触发格式化前后回调，但其递归子模板 `${name}` 中的 name 是文本插值，正常触发解析与格式化回调。

### 字符串递归展开的深度限制（Q10a：已确定 A，可配置且默认 64）

选项提供可配置的最大深度，默认 64，显式设置须为正整数。不使用非正值表示无限展开。根模板为第 1 层，每次将字符串值作为子模板评估时增加一层，在进入超过上限的子模板前失败，不截断输出也不把剩余占位符作为成功结果保留。

例如根模板为 `${a}`，a 的值为 `${b}`，b 的值为 `OK`，实际模板层级是 `${a}`（第 1 层）→ `${b}`（第 2 层）→ `OK`（第 3 层）。上限 3 可成功，设为 2 则进入第 3 层前失败。同层的 `${a}/${a}` 分别展开，不因引用总次数增加累计深度。

动态字符串索引的子模板共享当前模板深度，不从根重新计数。例如根模板 `${map[key]}` 为第 1 层，key 的字符串 `${name}` 展开为第 2 层，name 的字符串 Alice 作为子模板为第 3 层；返回后继续在第 1 层完成索引访问。随后若取得的 map 值也是字符串，该值的子模板从第 2 层开始，不累计之前已完成的兄弟展开。

这里限制引擎自动执行的字符串模板嵌套，不把普通成员链长度、索引语法嵌套或用户在回调中主动发起的另一轮 Evaluate 调用混成同一计数。其它资源边界属于单独议题，不宣称仅靠此限制就覆盖所有资源消耗。

### 活动引用重复的处理（Q10b：已确定 A，只通过深度限制终止过长递归）

首版以 Q10a 的最大展开深度终止过长的递归，不仅凭同名或同路径再次出现就判定循环；每次引用继续按 D42 查询来源。超过深度时报告超限，可携带引用链，不断言一定存在静态循环。

动态例子：模板 `${next}`；提供器第一次查询 next 返回字符串 `${next}`，第二次返回 `done`。允许这次展开成功（深度上限至少 3），不在第二次查询前按同名重复拒绝。

静态例子：a 固定返回 `${b}`，b 固定返回 `${a}`，在超过深度时失败。`${name}/${name}` 等独立引用分别求值，不维护全局已访问集合来拒绝重复引用。

### 变量解析与格式化回调（Q05a：已确定 A，并增加格式化前后回调）

评估器具有解析前、解析后、格式化前、格式化后四类回调，对应 Resolving、Resolved、Formatting、Formatted。这里的“解析”指变量取值过程，不将词法扫描通知与变量取值通知混为一谈。

已确定采用评估器实例事件，选项不保存回调。解析前接管完整引用、解析后调整对象值、格式化前调整输入或接管、格式化后调整输出文本的能力均已确定。上下文类型和成员名称见 R5，不因事件需求恢复 ProfileOptions 被否定的三个平行属性草案。

已确定的处理顺序：

```text
引用语法解析
→ 解析前回调
→ 取值与成员导航（解析前已接管时跳过）
→ 解析后回调（可调整未格式化的对象值）
→ 按选项递归展开
→ 格式化前回调（可调整输入或接管）
→ 默认格式化（格式化前已接管时跳过）
→ 格式化后回调（可调整输出字符串）
→ 插入结果文本
```

例如 order.Total 为 decimal 类型的 12.346，模板为 `${order.Total#0.00}`，且显式设置 InvariantCulture。解析后回调取得 decimal 值；若将它乘以 2，格式化前阶段面对的是 24.692 和格式 `0.00`，默认格式化后得到字符串 `24.69`。格式化后回调可将结果改为 `合计：24.69 元`，该文本直接插入结果，不再解释为模板。

递归发生在两组回调之间；递归模板中的引用及动态索引中的变量引用各自嵌套通知。通知粒度及各阶段修改、接管能力见已确定的 Q05b—Q05g，失败时的通知和异常传播见 Q06c—Q06d。上下文成员已经按 R5 落实；嵌套使用各自引用的源码位置及模板深度，不增加公开关联链。评估器不缓存变量值，不需要设计命中缓存时的通知分支，也不为回调公开全部内部执行状态。

### 回调的放置方式（Q05i：已确定 B，评估器实例事件）

四类回调在评估器实例上提供 .NET event，通过订阅配置；选项只保存文化区域、递归等设置。Resolving、Resolved、Formatting、Formatted 的名称、委托和上下文类型均已随 R5 确认。

公开 API 采用 EventHandler<T>，订阅示例包含 sender 和 context 两个参数。此前的单参数 lambda 只示意订阅位置，以当前确定的委托签名为准。以下示例只针对 person.Name 提供替代结果：

```csharp
evaluator.Resolving += (sender, context) =>
{
	if(string.Equals(context.Expression, "person.Name", StringComparison.OrdinalIgnoreCase))
	{
		context.Value = "匿名";
		context.Handled = true;
	}
};
```

不同时维护选项回调与实例事件两条通知路径。订阅在求值调用之间设置或调整，不改变 Q09h；单个事件存在多个订阅者时，按 Q05j 全部通知后检查最终 Handled。

### 多个事件订阅者与 Handled（Q05j：已确定 A，全部通知后检查最终标志）

解析前和格式化前事件按订阅顺序调用所有处理器，最后检查 Handled 决定是否执行默认处理。第一个处理器接管后，后续处理器仍可观察或调整结果；若后续处理器明确将 Handled 改回 false，则恢复本阶段默认处理。后置事件的 Handled 修改不会让已经完成的处理重新执行。

例如第一个 Resolving 订阅者为 person.Name 提供“匿名”并设置 Handled，第二个订阅者记录此次解析：第二个仍被调用并能看到“匿名”，最终 Handled 为 true 则不执行默认取值。任一处理器抛异常均按 D51 终止本次求值，剩余处理器不再执行，不为了凑齐通知次数继续调用。

### 解析回调的通知粒度（Q05b：已确定 A，按完整引用通知）

正常求值时，每个完整变量引用触发一组解析前后回调。`${person.Home.Address}` 只触发一组，解析后取得 Address 的最终对象值；不对 person、Home、Address 各自通知，也不对提供器集合的每次尝试分别通知。

动态索引参数中的变量仍是独立引用。例如 `${arr[index].Name}` 的外层引用一组，index 自身一组，后者嵌套于外层取值阶段；常量索引不增加解析回调。重复出现的引用各自通知，与不缓存变量值的决定一致。进入字符串递归时，新模板中的引用按同样规则通知。取值失败不触发该引用的解析后回调，见 Q06c。

对于上述动态索引示例，假设 index 返回整数，在未接管且正常成功时，回调顺序如下；index 作为原始下标值参与取值，本身没有格式化通知。字符串索引递归产生的额外子模板通知见 Q05h：

```text
解析前：arr[index].Name
  解析前：index
  解析后：index
解析后：arr[index].Name
格式化前：arr[index].Name
格式化后：arr[index].Name
```

### 解析前回调接管取值（Q05c：已确定 A，允许接管）

允许前置回调提供完整引用的结果，跳过默认来源查询、成员导航和该引用内部的动态索引求值，然后继续解析后、可选递归和格式化阶段。

例如解析 `${person.Name}` 时，前置回调可以将完整引用替换为字符串“匿名”，不再查询 person 或读取 Name。下例示意已确定的接管行为：

```csharp
context.Value = "匿名";
context.Handled = true;
```

设置 Value = null 并标记已接管仍是成功；不能用 Value 是否为 null 判断是否接管。接管只跳过取值，不绕过模板语法校验，也不自动跳过后续阶段。若完整接管 `${arr[index].Name}`，未执行的 index 引用不会产生通知。

### 默认格式化是否通知（Q05d：已确定 A，所有进入文本格式化的插值均通知）

凡是进入文本格式化阶段的插值，都触发格式化前回调，成功完成后触发格式化后回调，包括没有 `#format` 的 `${price}`、最终值为 null 的引用以及前置回调接管后的结果。无显式格式时 Format 为 null。格式化失败不触发格式化后回调，见 Q06c。

例如调用方希望统一记录数值输出，格式化后回调能同时收到 `${price}` 与 `${price#0.00}` 的格式化结果。普通模板文本不触发格式化回调。动态索引参数（如 `${arr[index].Name}` 中的 index）本身不进行文本格式化，其解析回调范围遵循 Q05b；字符串值的递归子模板遵循 Q05h。

### 解析后改写对象值（Q05e：已确定 A，允许改写）

允许替换最终对象值，包括设为 null。修改后的值继续进入可选递归和格式化，不重新执行来源查询或成员导航；动态索引引用的解析后回调也可调整原始下标值，该值用于索引访问，本身不进行文本格式化。

例如 `${order.Total#0.00}` 得到 decimal 值 100，可在解析后将值改为 90，随后使用格式 `0.00` 输出（区域设为 InvariantCulture 时为 `90.00`）。若改成字符串 `${fallback}`，则是否展开仍遵循递归选项；若改成 null，仍交给 .NET 格式化。

### 格式化前的调整与接管（Q05f：已确定 A，允许调整和接管）

允许调整当前值、格式和文化区域，也允许直接提供文本并标记接管，跳过默认 .NET 格式化，然后继续格式化后回调。调整只影响当前引用，不修改评估器共享选项，也不返回之前的取值或递归阶段。Value、Format、Culture、Text 和 Handled 仅为示意名称。

例如 `${status}` 的值是业务状态对象，可以直接提供文本“已完成”，不用改变对象的 ToString 实现：

```csharp
context.Text = "已完成";
context.Handled = true;
```

`${price#0.00}` 可将当前格式改为 `0.000`；临时指定当前引用的 Culture 不影响其它插值，保持 null 则沿用 .NET 默认行为。格式化前新增或替换的字符串作为格式化输入，不自动重启递归。

解析前接管与格式化前接管分别判断。解析前提供了对象值，不意味着跳过默认格式化；格式化前提供了文本，也不意味着跳过格式化后回调。不提前指定这两个阶段是否复用上下文类型或采用同名属性。

### 格式化后改写文本（Q05g：已确定 A，允许改写且直接输出）

允许替换最终文本，例如将 `90.00` 改成 `合计：90.00 元`，修改结果直接插入模板，不再执行取值、递归或格式化。

若把结果改成 `${other}`，输出就是字面文本 `${other}`，即使启用了字符串递归，也不回到递归阶段。回调提供 null 文本按 R4 交给 .NET 拼接；公开成员按 R5 实现。

### 查询时机与缓存（Q09c：已确定 A，每次引用重新查询）

每次引用都重新查询来源，评估器不缓存根变量值。需要缓存或稳定值时，由来源自行实现缓存或提供固定数据；这不限制模板语法解析结果的复用。

假设提供器每次读取 counter 都递增并返回一次，初始值为 0，且没有回调接管取值：`${counter}/${counter}` 输出 `1/2`。同一 provider 实例状态继续递增时，再次评估输出 `3/4`；来源返回什么由来源自身决定。

成员 getter 和索引访问也逐次执行，不缓存完整路径值。`${person.Score}/${person.Score}` 会分别查询 person 并读取 Score；即使来源两次返回同一对象，也不承诺两次属性值相同。

来源集合的调度规则见 Q09d；解析前接管和通知粒度见 Q05b、Q05c。已接管的引用跳过默认查询，其它引用继续逐次取值。此决定不要求给提供器或全部容器加锁，也不承诺共享来源的并发读取语义。

### 缺失、空值与错误（缺失、最终 null 与中间 null 已确定）

根变量未找到默认失败；成功取得的最终 null 交给 .NET 格式化；导航中间值为 null 时失败。其他情况需分别定界，不能统一归为“变量不存在”：成员不存在、索引越界、字典键不存在、getter 或提供器自身抛出异常、格式无效。

例如模板 `/srv/${environment}/app` 中的 environment 未定义，且调用方没有提供替代值：求值失败并报告 environment 缺失，不返回原始模板作为成功结果，也不生成 `/srv//app`。

解析前回调可以显式提供替代结果，见 Q05c。首版选项不增加缺失策略切换，也没有默认查询失败后的补值事件；缺失可通过 Resolving 接管完整引用处理。TryEvaluate 的签名及失败语义按 R5/R6 落实。

Q06a 已确定并经用户补充：成功取得的最终 null 不需要 Core 特殊处理，交给 .NET 格式化即可。以下是未使用自定义格式化行为时的默认结果，不是 Core 预先替换 null 的规则：

| 数据 | 模板 | 默认结果 |
| --- | --- | --- |
| remark 已定义，值为 null。 | `备注：${remark}。` | `备注：。` |
| person 存在，MiddleName 成员存在且值为 null。 | `${person.MiddleName}` | 空字符串。 |
| person 存在，Home 成员存在且值为 null。 | `${person.Home}` | 空字符串；没有继续访问 Home 的成员。 |

解析后及格式化前回调仍取得真实 null，随后将值交给基础类库；不提前把 null 改为 `""`，也不绕过调用方提供的格式化机制。回调通过对应上下文的 Value 属性改写值。

Q06b 已确定 A：成员链中途遇到 null 而无法继续导航时求值失败。假设 person 存在、person.Home = null：

| 模板 | 结果 |
| --- | --- |
| `${person.Home}` | 取值已完成，将最终 null 交给 .NET 格式化，默认得到空字符串。 |
| `地址：${person.Home.Address}` | 求值失败，报告 person.Home 为 null，无法继续读取 Address。 |

最终 null 的文本格式化与中间 null 的导航失败属于不同阶段。此决定不同时规定成员不存在、索引越界或字典键缺失的具体诊断。

模板入口始终返回字符串，见 Q09e。若以后需要返回单个引用的原始对象值，应另行设计明确的入口，不改变模板返回类型或绕过已确定的处理阶段。

外部执行异常统一包装并保留原异常，携带引用、模板位置和失败阶段，见 Q06d；字符串递归深度规则见 Q10a、Q10b；Try 入口的失败范围见 Q09f。诊断成员已经按 R6 落实，首版只保留失败层模板、引用、位置和深度，不新增公开引用链模型。

### 取值或格式化失败时的后置通知（Q06c：已确定 A，仅成功后通知）

对应阶段成功后才调用后置回调；前置回调显式接管也算成功。取值失败则不执行解析后及其后续阶段；格式化失败则不执行格式化后。已经完成的解析后通知不会撤销或重复执行。

例如 `${person.Name}` 的 Name getter 抛出异常，不调用解析后回调。若取值成功，但值的 .NET 格式化实现抛出异常，解析后已正常执行，格式化后不执行。

递归发生在解析后与格式化前之间：若子模板失败，外层已执行的解析后通知保持完成，外层不会进入格式化。若动态索引的引用失败，则外层引用也未完成取值，不调用外层解析后回调。

当前 ProfileReader.Session.ProcessDirective 在指令处理正常返回后调用 Processed，处理过程抛异常时不调用，新规则与这个已有通知习惯一致。不要求新评估器照搬 Profile 的实现或公开类型；后置回调不承担失败通知或 finally 清理职责。回调自身抛异常的表示方式见 Q06d。

### 外部执行异常的传播方式（Q06d：已确定 A，统一包装并保留原异常）

提供器、成员 getter、索引器、.NET 格式化实现及用户回调抛出的执行异常，统一包装为 TemplateEvaluationException，携带当前引用、模板位置和执行阶段，并通过 InnerException 保留原始异常。索引转换方法最终抛出的异常也按此处理。诊断成员见已确认的 R6。

发生此类异常后终止本次求值，不吞掉错误、不尝试下一来源，也不返回部分文本作为成功结果。评估器自身发现的语法错误、变量缺失、中间 null 等使用 TemplateEvaluationException 报告，不虚构一个不存在的原始异常。

例如模板 `用户：${person.Name}` 中，Name getter 抛出 InvalidOperationException：外层错误指出 person.Name 引用及取值阶段，InnerException 保留收到的原异常。若格式化后回调抛出异常，标记为格式化后回调阶段，不继续后面的插值。嵌套求值保留失败层位置与阶段，不在每层递归新增异常，见 R6。

### 模板求值入口的返回类型（Q09e：已确定 A，始终返回字符串）

新模板评估器的 Evaluate(text) 入口始终返回字符串，不根据模板形态切换到原始对象值。不预先修改现有 IExpressionEvaluator 接口，也不要求现在增加独立的原始值求值方法。

假设 count 是 int 类型的 42：`${count}` 返回字符串 `42`，`数量：${count}` 返回字符串 `数量：42`。即使模板只有一个引用，也正常经过递归和格式化流程，其回调行为与混合模板中的引用一致。

需要原始对象值的独立入口可按实际需求另行设计。null 输入参数的处理属于独立 API 参数边界，不由这里的输出类型决定。

### TryEvaluate 入口（Q09f：已确定 A，返回成功标记、结果及诊断）

Evaluate 在失败时终止，并通过异常报告；同时提供显式的 TryEvaluate 入口，供批量检查或由调用方集中收集错误等场景使用，不改变 Evaluate 的失败规则。

TryEvaluate 成功返回 true 和字符串结果，失败返回 false 和错误诊断。失败时不提供部分文本，结果输出为 null；成功时错误输出为空。语法错误、变量缺失、递归超限及已统一包装的来源/回调执行异常均作为求值失败返回；底层异常仍保留在诊断中。

例如调用方依次检查 `${name}`、`${missing}`、`${count}`，可分别记录成功结果或错误并继续处理下一条，不必为每条模板编写 try/catch。调用形式为 TryEvaluate(text, out result, out error)，错误类型确定为 TemplateEvaluationException，成功结果按 Q09e 为字符串。

非法 API 参数或无效选项配置不归为模板求值失败，这些调用错误仍抛异常；也不承诺捕获任意运行时异常。Try 失败不会回滚此前提供器或回调产生的副作用，不能先 Evaluate 再为收集诊断执行一次模板。异常与 Try 两个入口共享同一求值语义。

```csharp
}
```

Culture 默认 null，Recursive 默认 false，MaximumDepth 默认 64 且要求正整数。类型名保留 Template 前缀，以区分已有返回 object、包含 Global 和释放契约的 IExpressionEvaluator；现有接口不作为新模板入口的强制基类。首版不增加单次选项覆盖重载、原始对象求值重载或公开语法树；以后计算能力从已保留的 `${=...}` 分支扩展，不改变普通变量语法和模板的字符串返回契约。

事件采用 EventHandler<T>，sender 为评估器实例；这与仓库 CommandBase、MemoryCache 等既有事件的委托形态一致。两个上下文派生 EventArgs，前后阶段分别共享本次引用的对应上下文；解析与格式化使用不同上下文，避免混用两个阶段的接管状态。每次引用创建自身状态，不跨引用复用可变上下文对象。

### 事件上下文

以下属性已确认；只读成员用于生产调用方识别引用和位置，可写成员对应已经确认的介入能力。上下文由评估器创建，构造器不作为调用方入口；不为测试扩大任何内部状态的可见性。

两类上下文共同的只读元数据：

| 属性 | 类型 | 含义 |
| --- | --- | --- |
| Template | string | 当前层模板原文；递归时为正在展开的子模板，而非始终指向根模板。 |
| Expression | string | 当前完整变量引用的原始文本，含显式命名空间及导航路径，不含外层 `${}` 和格式后缀。 |
| Namespace | string | 根变量命名空间，默认作用域为 null。 |
| Name | string | 根变量名称，例如 app:person.Home 中的 person。 |
| Position、Length | int | Expression 在当前 Template 内的区间，位置从 0 开始，按 .NET 字符串 UTF-16 索引计数。 |
| Depth | int | 当前模板递归深度，根为 1；动态索引引用自身不因语法嵌套另增模板深度。 |

VariableEvaluationContext 的其它成员：

| 属性 | 类型及读写 | 含义 |
| --- | --- | --- |
| IsIndex | bool，只读 | 是否正在取得动态索引参数，便于订阅者区分参数取值与文本插值。 |
| Value | object，可写 | 解析前可提供替代结果，解析后为完成导航后的值；真实 null 保留。 |
| Handled | bool，可写 | 解析前显式接管默认取值；解析后修改此标志不重执行取值。 |

VariableFormattingContext 的其它成员：

| 属性 | 类型及读写 | 含义 |
| --- | --- | --- |
| Value | object，可写 | 格式化前面对的对象值，已完成可选递归；格式化后再改值不重格式化。 |
| Format | string，可写 | 当前引用采用的格式，未指定为 null；修改仅影响当前引用。 |
| Culture | CultureInfo，可写 | 当前引用采用的文化区域，初始取自选项；null 保持 .NET 默认。 |
| Text | string，可写 | 格式化前可提供接管结果，格式化后为即将插入模板的文本。 |
| Handled | bool，可写 | 格式化前显式接管默认格式化；与解析阶段的 Handled 相互独立。 |

共同元数据不要求另造一个公开基类；内部可复用不可变描述信息。上下文只为事件提供必要信息，不公开解析栈、执行会话、缓存或内部节点。动态索引字符串递归时，其子模板插值使用自己的上下文和当前位置，不能借用外层引用的范围。

### 诊断载体

由同一个 TemplateEvaluationException 承载 Evaluate 抛出的求值错误和 TryEvaluate 输出的 error，避免平行维护另一套错误对象；它派生 Exception 并保留 InnerException。已确认的附加只读成员如下：

| 属性 | 类型 | 用途 |
| --- | --- | --- |
| Code | string | 稳定的错误标识，用于程序判断；例如语法错误、变量缺失、空目标导航、索引失败、深度超限、预留计算不支持、外部执行失败。具体码值由实现统一命名。 |
| Stage | TemplateEvaluationStage | 区分语法解析、解析前事件、取值与导航、解析后事件、递归、格式化前事件、默认格式化、格式化后事件。枚举成员由实现按这些阶段命名。 |
| Template | string | 错误所在层的模板原文。 |
| Expression | string | 可识别时为失败引用；例如普通文本转义错误时可为空。 |
| Position、Length | int | 错误范围；未闭合占位符仍按 D26 指向 `${` 起点，不强制与事件中的引用区间相同。 |
| Depth | int | 错误所在模板层级。 |

语法、缺失和超限等由引擎检测到的错误可以没有 InnerException；外部执行错误保留原异常。嵌套传播应保留最初失败位置和阶段，不在每层改写成“外层递归失败”；R6 已确定首版只提供失败层模板、位置和深度，不新增公开引用链模型。不为收集诊断而重复查询来源或重执行模板。错误码用于稳定判断，Message 使用仓库要求的资源，不将本地化文案写进单元测试断言。

### 使用形态

```csharp
var options = new TemplateEvaluatorOptions
{
	Culture = CultureInfo.InvariantCulture,
	Recursive = true,
};

var evaluator = new TemplateEvaluator(options);
evaluator.Providers.Add(runtimeProvider);
evaluator.Providers.Add(defaultsProvider);

evaluator.Resolving += (sender, context) =>
{
	if(string.Equals(context.Expression, "person.Name", StringComparison.OrdinalIgnoreCase))
	{
		context.Value = "匿名";
		context.Handled = true;
	}
};

if(evaluator.TryEvaluate("姓名：${person.Name}", out var text, out var error))
	SaveResult(text);
else
	RecordError(error);
```

事件属于 evaluator，Options 只包含设置。多个评估器可显式共用 options，但各自维护提供器集合和事件订阅；求值期间配置稳定的约定对所有共享者适用。此示例中的来源实例及 SaveResult/RecordError 由调用方提供，不是新增的框架成员。

### R1：格式空白

只忽略格式首尾未被引号或反斜杠保护的空白。`${n# 0.00 }` 传递 `0.00`；`${date#yyyy-MM-dd HH:mm:ss}` 保留日期与时间中间的空格；`${n#'总计 '0.00}` 保留引号内的空格及引号本身。`${n# }` 处理后为空，按已确定的非空格式要求失败。

普通表达式模式的跳过空白行为不直接用于格式文本，不删除全部未受保护空白。格式回调随后主动设置的 Format 直接交给基础库，不再次按模板源码规则处理。

### R2：成员和索引匹配

索引参数绑定时统一调用 Zongsoft.Common.Convert.ConvertValue(value, targetType)，targetType 为目标索引器参数或容器键/下标的类型。数组、列表、字典和自定义索引器沿用这套转换能力，不另造模板专用转换矩阵。使用不带失败默认值的重载，转换失败按求值错误报告。

| 目标与输入 | 绑定行为 |
| --- | --- |
| Dictionary<long, string>，`${map[1]}` | int 常量 1 转为 long 键 1。 |
| Dictionary<long, string>，`${map['1']}` | 字符串键 `"1"` 转为 long 键 1。 |
| int 下标，动态变量 index = `"1"` | `${arr[index]}` 在绑定时将字符串转为 int 的 1。 |
| int 下标，动态字符串递归结果为 `"1"` | 先完成递归，再在绑定时转为 int 的 1，不增加参数格式化事件。 |
| int 下标，参数为 null | 沿用 ConvertValue 的 GetDefaultValue 行为，得到 int 的 0；这不是中间 null 对象的导航规则。 |
| object 参数 | ConvertValue 保留原值，int 与 long 对象仍可区分。 |
| long 参数，输入为 `"abc"` | 转换失败，包装转换方法抛出的异常并终止求值。 |

索引器先匹配参数个数，再优先精确类型和唯一最具体的可直接赋值签名；确需转换时按目标参数类型调用 ConvertValue。转换候选仍无法唯一确定时报告歧义，不通过反射枚举顺序或调用多个 getter 试错决定。普通成员忽略大小写后仍存在多个同等有效目标，例如同一类的 Name 和 NAME，也报告歧义，不取反射返回的第一项。继承/接口的重复同一读取契约需在候选整理时去重，不人为制造歧义。

可确认的成员或键缺失、越界、参数不匹配和不可读取均求值失败；自定义读取器成功返回 null 仍按成功 null 处理。首版不再为每类失败增加保留原文/替换空字符串的选项，前置事件可接管完整引用。Type 对象按普通实例的公共读取契约处理，不自动切换为其表示类型的静态访问；公共接口读取和数组、列表、字典适配由实现核验。

字符串、数值、null/DBNull、枚举及自定义 TypeConverter 等具体转换语义由 Common.Convert 统一负责，不增加模板专用的精度、舍入、空值或区域预处理。Options.Culture 仍用于模板格式化，不为转换临时修改线程区域；转换采用 Common.Convert 的既有区域行为。字面量解析阶段继续遵循固定小数点规则。

转换发生在取值、Resolved 事件以及可选字符串递归之后；回调仍能看到转换前的原始参数值。转换方法最终抛出的异常作为 TemplateEvaluationException.InnerException 保留。当前 Common.Convert 内部可能已吸收底层转换异常并抛出自己的 InvalidOperationException，模板层不宣称能够恢复该方法未抛出的底层异常。

### R3：解析与执行时机

每层模板先完成语法解析，再按从左到右的顺序查询来源并触发事件。例如 `${name}-${bad` 在调用 name 的提供器之前就报告未闭合语法错误，避免已知无效的根模板产生部分取值副作用。

此规则只覆盖当前已取得的模板。递归时先获取字符串值，才能解析该子模板；若 name 的值是非法子模板，之前已经完成的取值和事件不回滚。外部 getter 或来源执行失败也不产生事务回滚。

### R4：调用边界

Evaluate(null) 和 TryEvaluate(null, ...) 均抛 ArgumentNullException，符合已确定的“非法调用参数不由 TryEvaluate 吞掉”规则。Evaluate("") 返回空字符串，TryEvaluate 对空串返回 true，均不触发变量事件。空白模板是普通文本，按模板文本规则保留。

格式化前接管或格式化后回调把 Text 设成 null 时，不新增求值失败或 Core 的空值替换逻辑，直接交给 .NET 文本拼接。格式化前对 Value 设置 null 仍交给 .NET 格式化；这与输入模板为 null 是不同场景。

### R5：公开入口和事件上下文

采用上方整份 API：TemplateEvaluator、TemplateEvaluatorOptions、IVariableProvider，Evaluate/TryEvaluate 两入口，固定引用的 Providers/Options；选项只有 Culture、Recursive、MaximumDepth。构造仅接可选 options，来源通过集合注册，不新增逐调用覆盖配置的重载。

四个事件为 EventHandler<T> 形式的 Resolving、Resolved、Formatting、Formatted；前两者使用 VariableEvaluationContext，后两者使用 VariableFormattingContext。上下文共同提供 Template、Expression、Namespace、Name、Position、Length、Depth；取值上下文另有 IsIndex、Value、Handled，格式上下文另有 Value、Format、Culture、Text、Handled。只读/可写边界按上方属性表，构造由内部控制。

不为复用上下文属性增加公开基类。已有脚本 IExpressionEvaluator 不强制成为模板评估器的基类；原始对象入口、公开 AST、编译模板接口等没有当前需求的能力不作为首版前提。

### R6：诊断载体

采用 TemplateEvaluationException，同时作为 Evaluate 抛出的异常和 TryEvaluate 的错误输出。附加只读成员为 Code、Stage、Template、Expression、Position、Length、Depth，外部异常存入 InnerException；Stage 使用 TemplateEvaluationStage 枚举，具体码值和枚举成员命名由实现按本表涵盖的阶段整理。

递归错误保留真正失败的子模板及其位置，不在外层重复包装而丢失最初阶段。假设根模板为 `${message}`、message 的值为 `${missing}`：诊断指向子模板 `${missing}`、Depth=2。首版不增加公开的父级上下文或引用链集合；以后确有诊断展示需求再扩展。位置使用 .NET UTF-16 索引，错误消息使用资源，测试断言类型、码值和位置。

### 由实现统一处理的事项

这些事项已归入实现：Lexer 改造及词法边界修正、token 源码位置、上下文关键字识别、负数和数值范围、内部节点/栈组织、来源名称比较契约、Reflection 的参数传递和集合适配、ConvertValue 参数绑定、错误资源、下游影响及多目标框架验证。实现采用已确认的公开接口，测试不要求扩大可见性。

首版不新增自动语法缓存、额外公开资源限制选项或仅为测试使用的入口；必要的内部执行保护按实现处理，已有递归深度契约不变。

第二阶段 Profile 仍需设计简洁的选项入口、扩展方法如何取得评估器、导入参数的求值时机；第三阶段 tools 负责来源适配、调用迁移和模板更新。这些已明确留到后续阶段，不影响第一阶段设计完成。

## 解析实现结构（采用既有 Lexer）

按用户意见，采用并完善 Zongsoft.Expressions 的 Lexer/TokenScanner/Tokenizer，读取成员复用 Reflection.Reflector，并由内部 MemberAccess 负责公共实例契约筛选、歧义判定和索引绑定。模板分区和引用语法位于 TemplateEvaluator.Parser 私有类型中，不另造平行的数字、字符串和标识符词法规则。已确定的语言规则优先于旧实现，不考虑兼容性。

### 模板分区和语法层

- 模板层负责普通文本、转义、插值起始、引用和格式的切换；Lexer 的分区/扫描能力按需要扩展。普通文本保留空白，变量引用拒绝语法空白，格式空白按 R1 处理，不能统一套用普通表达式的跳过空白行为。
- 引用层消费词法结果，组织命名空间、根变量、成员链及多参数/嵌套索引。NumberTokenizer 在模板索引模式下将负号并入数字 token，通用 Lexer 仍输出独立负号；不因 Lexer 能识别运算符就开放索引中的算术或方法调用。
- 分析结果保留起始位置和长度；节点和内部栈按执行需要保持最小，首阶段不公开通用语法树，不为测试扩大可见性。
- 解析不调用变量来源、不读取 getter、不触发取值/格式化事件；执行层才调用提供器和 Reflection。先完整解析当前层再执行，见 R3。
- 每个引用分区调用一次 Lexer，保留 UTF-16 源码区间并复用词素组织嵌套索引；没有语法缓存或结果缓存，不承诺未经测量的零分配或倍数提升。

示例 `总额：${app:orders[indices[0]].Total#0.00}` 的分析结构：

```text
文本：总额：
变量引用：
	命名空间：app
	根变量：orders
	索引参数：默认命名空间中的 indices[0]
	成员：Total
	格式原文：0.00
```

orders 从 app 查找，indices 从默认环境查找；这些查找发生在执行阶段。索引参数不会隐式继承外层 app 命名空间。

### 现有设施的改造范围

TokenScanner 增加 Scan(out position, out length)，统一字符串和流的字符读取与回退；流以 UTF-8/BOM 读入字符缓冲，扫描器释放时关闭输入。IdentifierTokenizer 使用 ASCII；StringTokenizer 与模板文本共享七种转义；NumberTokenizer 使用固定区域并处理 long 范围；LiteralTokenizerBase 修复关键字前缀与末尾部分匹配。模板分区控制文本、引用和格式的空白契约。

模板的引用节点消费上述词法设施，支持命名空间、负数和动态索引组合。内部 Reflection.MemberAccess 调用 Reflector 读取字段、属性和索引器，使用 ConvertValue 绑定参数；数组直接按维度读取。原有 MemberExpressionParser/Evaluator 没有参与新引用语法，也未改动其既有入口；它们不承担模板的来源、事件或递归契约。

模板节点、解析器及语法嵌套保护均保持私有；MemberAccess、共享转义函数和有符号数字构造仅在生产路径需要的位置使用 internal。未为单元测试增加可见入口。

实现中验证成员/索引实际求值能力，并检查 Plugins 等共享代码的直接下游；不把“需要验证影响”转化为“不允许修改”的限制。

### 未来计算阶段

`${=...}` 进入计算分支；第一阶段按 D38 明确失败。未来计算复用同一词法设施，在其上增加语法分析（例如 Pratt 或递归下降），处理优先级、结合性及括号。词法分析本身不承担完整表达式解析。

新增计算分支必须共享已确定的 ASCII 标识符、字符串转义、命名空间和变量导航语义。分词与语法解析需保留原文位置，并与模板层配合识别顶层 `#format` 和结束标记，不能直接在任意 `#` 处截断。现有设施按实际需求修改，不为测试扩大可见性。
